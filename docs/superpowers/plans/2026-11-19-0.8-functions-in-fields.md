# Functions in fields (0.8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lift E0304 so struct fields, enum payloads and type arguments can hold functions, in both compilers and both backends, and write down the three 0.8 design decisions in SPEC.md, ROADMAP.md, the book and the design doc.

**Architecture:** Every rule that refuses functions today (`dyn`, map keys, `==`, purity, `json`) looks at a type's own shape, because a function could never hide in a field. Lifting E0304 means those rules must also see functions held through fields. That is done exactly the way capabilities held through fields already are: a per-type table, computed once from the field types (Types.authority in OCaml, `with_authority` in the self-hosted compiler), recording the path to the first function a struct or enum holds. The rules then ask that table.

**Tech Stack:** OCaml compiler (`src/`), self-hosted compiler in Limen (`selfhost/`), C runtime, the book (`../limen-book`, Python build).

**Spec:** `docs/superpowers/specs/2026-11-19-0.8-design-questions-design.md` (0.8 part only: sections 2 and 3, "Order and releases" items 1 to 3. `mut` parameters are not in this plan.)

## Global Constraints

- Every change goes into both compilers (`src/` and `selfhost/`) and both backends; the self-hosted compiler stays at the bootstrap fixed point.
- E0305 (channels, `Atomic`, `Shared` in fields) is unchanged.
- E0304 is retired the way E0301 was: never reported, its diag text and SPEC.md row say "no longer reported".
- British spelling, no em dashes, no emojis, in code comments, messages and docs.
- No Claude attribution in commits (no `Co-Authored-By`, no session links). Commit locally per task; never push without Alfonso saying so.
- Verification before calling anything done: `dune build`, `dune exec ./test/test_limen.exe` all passing, `LIMEN_BOOK=../limen-book sh selfhost/check.sh` exit 0, `sh selfhost/bootstrap.sh` reaching the fixed point. Never rebuild while check.sh runs.
- Messages name the path to the function the way authority paths are named today: `` `App` holds a function through `App.router.on_get` ``.

## Review Focus

1. A function held two levels down and through a list (`struct App { routes: List[Route] }`, `struct Route { run: fn() }`): `App` must be refused by `==`, `dyn`, map keys and `json`, with the path `App.routes.run`. Test in Task 1.
2. The pure-call optimiser (section 14) must not keep or reuse a call whose argument holds a printing closure in a field: calling it twice in a loop prints twice. Test in Task 2.
3. A recursive type holding a function (`enum Chain { Link(fn() -> Int, Chain), End }`) must not loop the table computation, and must run and free cleanly natively. Tests in Tasks 1 and 2.
4. A closure in a field that captured a capability and a list is freed when the struct goes: no leak under `LIMEN_LEAKCHECK=1`. Test in Task 2.
5. A method value stored in a field (`Handlers { on_get: srv.handle }`) holds its copy of `srv` and runs in both backends. Test in Task 2.

  {|struct Server { name: Str }
fn handle(self: Server, path: Str) -> Str { "{self.name}: {path}" }
struct Handlers { on_get: fn(Str) -> Str, on_missing: fn(Str) -> Str }
enum Chain { Link(fn(Int) -> Int, Chain), End }

fn main(root: Root) {
    let out = root.stdout
    let tags = ["a", "b"]
    let srv = Server { name: "srv" }
    let h = Handlers { on_get: srv.handle, on_missing: |p| "missing {p} {tags}" }

    for _ in 0..<2 { let _ = shout(loud, "x") }
}|}
