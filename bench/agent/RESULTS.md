# Agent benchmark results

The phase 4 gate: a coding agent passes a 50-task benchmark using only the spec.

## Setup

- 50 tasks in `tasks/`, covering basics, collections, user types and generics, string parsing, capabilities and concurrency (groups, channels, sockets). They are generated by `make_tasks.py`.
- Expected outputs in `expected/` are computed by independent Python code, not by Limen.
- Five fresh Claude subagents each solved 10 tasks. Each was told to read only `SPEC.md` and its own task directories, with no access to the compiler source, tests, examples or expected outputs. It used only the `limen` CLI (`check`, `run`, `explain`, `fmt`).
- `grade.py` runs every solution from a fresh copy of its task directory, with that task's grants, and compares stdout exactly. It also flags solutions that contain their expected output.

## Run 1 (2026-11-11)

| Backend | Passed |
| --- | --- |
| Interpreter (`limen run`) | 50/50 |
| Native (`limen run --native`) | 50/50 |

Two solutions contain their output literally, and both are legitimate: task 01 asks to print a fixed string, and task 41 writes a given string to a file and reads it back.

The agents for tasks 41-50 started on an older `SPEC.md` that did not document channels or sockets yet. It was updated during the run, and those agents were told to re-read it.

Four run 1 solutions (31, 32, 35, 44) call `unwrap_or`, which was later replaced by the `??` operator. They are kept as the agents wrote them, so they no longer compile; `limen check --json` offers the rewrite as an automatic fix.

## What the agents reported

Their notes became spec clarifications or tracked gaps:

- **Missing types and features:** there is no tuple, map or character type, no ranges, no `remove`/`insert`, and no custom-order sort. The spec now says so up front and gives the idioms (structs, linear search, `split("")`, `while` counters).
- **Match arms:** a statement in an arm needs a block (`None => { more = false }`). Now stated in section 7.
- **`split`:** keeps empty pieces. Now stated, with an example.
- **Keywords as names:** using one (`let group = ...`) gave a bare parse error. It now explains that it is a keyword and suggests another name.
- **Unknown methods:** they give no suggestion when no similar name exists. Still open.
- **Mixed result types:** every task in a group must return the same type, so tasks run only for their side effects return a dummy value. Still open.
